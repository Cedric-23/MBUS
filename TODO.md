# Commuter live bus tracking and ticket update

- [x] Downloaded PDF tickets include the same signed, scannable boarding QR code as the on-screen ticket, with a readable ticket code and enough space to avoid clipping.
- [x] Commuter bottom navigation is Home / Schedule / Live / Trips / Waiting, with Live centered next to Schedule and linked to bus-only tracking.
- [x] Reserve seat becomes Pick up on the schedule when a trip has departed, is inside the existing 30-minute reservation cutoff, or no reservation seats remain. The Live page does not arrange pickups.
- [x] Live is bus-only tracking. Commuters can choose a current Boarding/Departed bus and view its road path and latest operator GPS point. Commuters pin their pickup in the dedicated pickup flow and manage their waiting request in the Waiting navigation page. Operators and admins manage waiting riders in their separate Waiting navigation page, not on Riders or scattered pages.
- [x] After login, operators explicitly enable GPS and grant browser location permission on the Dashboard. Their GPS pin is visible there, but it is uploaded only for an assigned Boarding/Departed trip. Sharing pauses in the background and stops when the page closes. Admin waiting remains in its admin workspace.
- [x] The changes include an additive database migration, local-only tests and setup instructions. Applying migrations 10 and 11 to Supabase remains a manual deployment prerequisite; they have not been run against production.
- [x] Redesign only the commuter Waiting page to mirror the operator map/list in reverse: do not show the tracking map or bus row until the commuter has marked themselves waiting. Before that, show a concise empty state and one path to the existing schedule/pickup flow. Once waiting, show only that trip's bus pin and the commuter's profile-photo pickup pin, labeled pickup distance, road route/ETA and Focus bus / Full route control; tapping the bus/row focuses the map. The waiting row offers Cancel. Switching buses requires canceling first; cancellation remains available if the trip has ended. Keep these waiting controls off Live, which remains bus-only route tracking.
- [x] Let the commuter toggle tracking of their waiting bus by clicking its row or map pin, as operators toggle a selected rider: tracking on focuses the bus and pickup and shows its road path; clicking again pauses focus/path and leaves a muted, reselectable bus pin. Cancel remains a separate action.
- [x] Restore operator bottom navigation to Home / Trips / Scan / Riders / Waiting, with Scan in the center and no Live tab. Redirect the old operator Live-map URL to Scan so Live no longer replaces the scanner.
- [x] Make the commuter Waiting controls more compact so they cover less of the map, while keeping bus tracking, route details, cancellation, and map attribution accessible on mobile and desktop.
- [x] When an operator marks a trip Arrived, the passenger Trips page shows an accessible completion confirmation, refreshes the status while open, and Trip History retains the confirmation; status lookup is limited to the signed-in passenger’s boarded reservations.
- [x] Admin Manage Routes keeps the existing routes, removes route creation and deletion, and allows only fare edits with CSRF protection and server-side fare validation.
- [x] Harden commuter email signup: keep the account unverified until its six-digit code is entered; code expires after 15 minutes and locks after five incorrect attempts; permit one resend per 60 seconds and accept at most five code-delivery requests per email/hour and 120 across the service/hour, enforced transactionally over sliding windows (a request still counts if later account creation or delivery fails); use any configured SMTP, Brevo, or mail-relay transport; preserve admin-reviewed driver/conductor applications while limiting field-validated submission attempts to three per email/hour and 30 across the service/hour, counted before file processing or persistence.
